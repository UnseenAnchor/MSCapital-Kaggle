# 迭代复盘：Event256 方向穷尽（多子种 / 512 / 容量 / 强模型融合）

## 背景

Event256（32→256事件，Public +0.001 → 0.146）确立"扩展输入信息量"有效后，沿同方向测试了4个分支，全部为负结果，说明该方向已基本收敛。

## 关键数据事实

- order / transaction 流 `seconds_before_predict` **max=60s**（中位30s）——本身只覆盖最近1分钟，无隐藏历史窗口。
- market 流 max=600s，中位299s，v3 已用 LEN_M=200（≈全分辨率）。
- 故 Event256 的增益本质是"恢复60秒内的**逐事件分辨率**"（32→256采样），而非"更长历史"。

## 四个分支实验（proxy OOF，事件单模型或栈融合）

| 分支 | 结果 | 结论 |
|---|---|---|
| 多种子 s13/s77 | 0.13217 / 0.13209 vs 0.13180 | 方差已消除，无收益 |
| 512长度 | 0.12948 vs 0.13180 | 尾部噪音>尾部信息，256为甜点 |
| D96容量 | 0.13150 vs 0.13180 | 数据上限非模型容量 |
| 强模型融合 | fusion 0.142 vs v3 0.147 | 见下 |

## 强模型融合（market@200 + flow@60 + raw order/tx@256，五流）

- 新增 `src/build_raw_event_grid.py`（掩码感知标准化 raw 事件 mmap）、`src/train_fusion_raw_event.py`；
- Proxy best_raw **0.14195**（v3 单模型约0.145，栈0.15865）；
- 融合与 v3 相关性 **0.803**，与 event256 相关性 0.672，与 target 0.142；
- 栈+融合：5%=0.1591、10%=0.1594、20%=0.1596，均远差于栈+event256(12%)=0.1603。

**结论**：把 raw 事件端到端喂给强模型，模型变弱（0.142<0.147）且多样性下降（与v3相关0.80>event256的0.66）。Event256 的 +0.001 来自**多样性**而非信息强度；同输入融合会破坏这种多样性。

## 现状

- 事件旁路（event256）信息量封顶 ~0.132（512/D96/多种子均无效）；
- 强模型融合 raw 事件无效；
- order/tx 无隐藏历史，market 已用全分辨率。

"扩展输入信息量"方向已收敛于 event256（已获 +0.001 → Public 0.146）。

## 唯一未测分支（需另行立项）

**事件对齐合并时间线**：把 market 快照与 order/tx 事件按时间合并为单一序列（约336时间步，含"类型"编码），让模型看到每笔交易所处的订单簿状态（order-flow→price 动态）。这是经典微观结构信号，与快照模型、事件模型都正交，但工程量较大（特征工程+新模型），且强模型融合的负结果削弱了预期。是否立项由用户决定。
